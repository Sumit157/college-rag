# Contributing

## Workflow
1. Work within the current development phase.
2. Create a focused branch.
3. Make small, testable changes.
4. Run relevant tests before moving forward.
5. Update docs when architecture or behaviour changes.
6. Do not start future-phase features early.

## Principles
- Local-first and privacy-friendly.
- Document-grounded answers only.
- Evidence must be traceable.
- Keep LLM, embedding and vector-store integrations replaceable.
- Prefer simple, readable code.
