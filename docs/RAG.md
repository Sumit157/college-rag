# RAG

## Core pipeline

```text
Question
  ↓
Query analysis
  ↓
Query embedding
  ↓
MongoDB vector search
  ↓
Metadata filtering
  ↓
Evidence selection
  ↓
Context construction
  ↓
Local LLM
  ↓
Answer
  ↓
Programmatic citations
```

## Document-only rule

The assistant must answer from retrieved uploaded material only.

The model must not use its pretrained knowledge to fill missing information.

If evidence is insufficient:

> I couldn't find enough information about this in the uploaded study material.

## Evidence objects

Every retrieved chunk should become an evidence object containing:

```text
id            (e.g. "evidence-1")
document_id
filename
page
section
chunk_id
text
relevance     (cosine similarity clamped to 0..1)
```

Evidence objects are retained through the request and returned to the frontend.

## Answer reasoning

The system should perform structured internal reasoning over the retrieved evidence, but **must not expose private chain-of-thought**.

Instead, expose a concise evidence explanation:

```text
Answer
↓
Supported by
- OS Notes.pdf · p.42
- OS Notes.pdf · p.43

Relevant context
- Memory Management section
- Paging definition
```

This lets the user verify the answer without revealing hidden reasoning.

## Context construction

Before generation:
1. Remove duplicate chunks.
2. Prefer high-relevance evidence.
3. Preserve document/page boundaries.
4. Keep context within the model limit.
5. Reject clearly irrelevant evidence.

## Citation rule

Citations are generated by application code from retrieved evidence. Never allow the LLM to invent filenames, pages or sections.
